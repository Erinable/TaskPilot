# macOS 安装包、数据恢复与手工更新

TaskPilot 目前只支持 macOS，尚无已发布的公开下载。仓库可生成 Apple Silicon（arm64）和 Intel（x64）的 DMG、ZIP；当前使用不需要开发者账号的 ad-hoc 临时签名，没有 Developer ID 签名或 Apple 公证。本文描述分发准备和验收要求，不代表各机型已经实机验收。

## DMG、签名与公证

制作和分发 DMG、ZIP 本身不需要付费 Apple 开发者账号。开源项目的 GitHub Release 也可以提供未签名或临时签名的安装包；是否具备开发者签名、公证，不能从 DMG 扩展名判断。TaskPilot 使用 `identity: '-'` 的临时签名保持两种架构的 App 包有效，这不校验开发者身份，也不代表通过公证。

[Apple 的 Developer ID 说明](https://developer.apple.com/developer-id/)要求获取 Developer ID 证书的团队加入 Apple Developer Program。Developer ID 签名校验开发者身份；公证服务检查已签名的软件并生成 ticket，改善 Gatekeeper 下的首次打开体验。它们是当前临时签名分发方式的可选升级路径，不是制作 DMG 的前提。以后采用此路径时还要配置必要的 hardened runtime、entitlements、公证与 stapling，并重新验证 CLI 和隔离行为。当前手工构建工作流不会使用证书或上传公证。

SHA-256 只能说明安装包是否与清单一致。安装包和清单同时被替换时，哈希一致也不能证明来源可信，更不能代替开发者签名或安全审查。

## 构建与校验值

安装依赖后，在仓库根目录运行：

```bash
npm run dist
npm run dist:checksums
```

默认生成本机架构。指定架构：`npm run dist -- --arm64 --publish never` 或 `npm run dist -- --x64 --publish never`；同时生成两种可用 `npm run dist -- --arm64 --x64 --publish never`。使用新的工作副本或干净的输出目录，避免旧版本安装包混入清单。

校验脚本也可单独运行 `node scripts/artifact_checksums.ts <目录>`。它按文件名排序，流式计算目录顶层 `.dmg` 和 `.zip` 的 SHA-256，写入 `SHA256SUMS`，忽略解包后的 App、调试 YAML 和 blockmap。没有安装包、遇到符号链接或无法安全表示的文件名会失败，保留原清单。重新打包后必须重新生成清单。

维护者可以在 GitHub Actions 手动运行 **Build macOS packages without Developer ID**：

1. 选择待验证的分支或 ref，运行 `distribution.yml`。
2. 分别下载 arm64、x64 的 Artifacts。每个附件包含对应安装包和 `SHA256SUMS`，保留 14 天。
3. 记录提交 SHA、版本、日志、哈希和验收结果。验收后再由维护者安排长期下载或 GitHub Release。

工作流只有手动触发，仓库权限只读，不创建 tag、Release、推送或调用真实模型。同一 runner 的跨架构打包成功不等于两种芯片的 Mac 都已原生运行通过。

## 下载、安装和首次打开

在“关于本机”确认芯片：Apple 芯片选择 arm64，Intel 选择 x64。从可信来源下载同一次构建的安装包和校验清单。

若目录包含清单内全部安装包，在该目录运行：

```bash
shasum -a 256 -c SHA256SUMS
```

每项应显示 `OK`。只下载了一个文件时，可运行 `shasum -a 256 "实际文件名.dmg"` 并逐字符比较清单对应的 64 位十六进制值。不要忽略其他文件缺失导致的校验失败。校验不一致时停止安装并重新获取文件。

1. 打开 DMG，将 App 拖入“应用程序”，退出 DMG 后从“应用程序”尝试启动。ZIP 则解压后将 App 放入“应用程序”。
2. 若系统提示开发者无法验证或 Apple 无法检查恶意软件，先确认来源与哈希。确定信任后，按 [Apple 官方步骤](https://support.apple.com/en-us/102445#openanyway)，在“系统设置 → 隐私与安全”点击“仍要打开”（Open Anyway）。
3. 再次确认是刚选择的 TaskPilot 后点“打开”，按系统要求认证。后续通常可双击打开。

官方流程要求先尝试打开。受组织管理的 Mac 可能无法建立例外，请由管理员决定。不要全局关闭 Gatekeeper 或批量清除 quarantine 属性。“会损坏电脑”、恶意软件或文件损坏提示不能一律当成未签名警告，应停止打开并核对来源。

打包 App 自带 Electron/Node，但 git、模型 CLI、登录和项目工具链仍由用户准备。Finder 启动找不到 nvm/Homebrew 命令时，在“设置 → 运行环境”选择“从登录 shell 读取”。

## 应用内备份与恢复

“设置 → 数据 → 创建备份”会生成带版本、文件清单、SHA-256 的本地文件夹。备份前先保存正在编辑的正式内容，等待或取消后台任务；备份期间不要用其他编辑器修改默认笔记目录。

备份包括全局偏好、仓库登记、各仓库需求与进度、课程、掌握度、私有 lab、默认笔记目录和未提交表单草稿。它不复制项目源代码、外部笔记库、CLI 认证、运行中 Agent 的临时副本、日志或 Chromium 缓存。外部笔记目录会列在备份信息中，必须另行备份。备份含私人学习材料和需求，文件权限按本地私有数据设置，请放在可信位置。

恢复步骤：

1. 保存当前编辑内容，停止后台任务，选择完整备份文件夹。应用会检查路径、文件大小、SHA-256、允许的目录和存储版本；符号链接和特殊文件不接受。
2. 核对预览中的创建时间、应用版本、文件数、草稿数及外部笔记路径，再确认“准备恢复”。
3. 点击“重新启动并恢复”。应用关闭时先完成正常落盘，下次打开、加载任何业务数据之前换入暂存快照。中途退出会按恢复记录在下次启动继续，不会把已经换入的目录当成旧目录覆盖。
4. 恢复前原件保存在数据目录旁的 `taskpilot.restore-history/<恢复编号>/`。有效的历史快照也可以重新选择恢复；原本已损坏的数据仍需保留并修复，不应直接重新使用。
5. 核对仓库、需求、课程、掌握度和草稿。项目源代码及外部笔记不会回退；仓库或笔记路径变了时，使用相应的重新选择/重定位入口。

应用无法启动时，启动错误页仍有“从备份恢复”入口，由原生对话框预览并确认。JSON 损坏时会保留原文件并显示位置；可先复制现场，再使用有效备份恢复，或修复 JSON 后点重试。不要删除损坏文件来掩盖问题。当前文件格式来自更新版本时，应先使用兼容的新版本处理，旧版不会清空它来恢复。

恢复会保留原件并使用持久化的恢复记录，但不是文件系统级的整目录事务；磁盘不可写或目录状态冲突时会停止并保留现场。请保留快照与恢复历史，按错误信息排查后重试。

## 手工更新与故障反馈

1. 在应用内创建备份，另行保存外部笔记、项目仓库及未提交改动，记录旧版本并保留旧安装包。
2. 正常退出，校验新安装包，用新版替换“应用程序”中的旧 App，不删除数据目录。
3. 打开新版，核对关键记录、CLI、笔记目录及仓库路径。
4. 新版异常时先保留日志与当前数据。回退须使用旧版能理解的数据备份，不让旧版直接写入新版格式；必要时在 App 完全退出后还原完整的对应版本数据副本。

“设置 → 数据”提供“复制诊断信息”和“打开日志目录”。诊断文本只含版本、平台、PATH 来源和 CLI 名称，不含认证、源码或日志正文。反馈时另附操作步骤与界面错误代码；分享日志前检查私人路径和内容。应用不自动上传诊断或遥测。

## 公开分发前验收

每个版本记录提交 SHA、哈希、macOS、芯片、CLI/工具链版本、结果和未解决问题。下面只能在实际验证后勾选。

- [ ] SHA-256 完整校验，文件名、架构、版本与发布说明一致。
- [ ] 在 Apple Silicon、Intel Mac 分别记录安装包首次打开、Finder/Dock 启动与 Gatekeeper 流程；未覆盖组合标明未验证。
- [ ] 内置课程、脚本与 wrapper 可找到，应用不依赖开发服务器。
- [ ] 缺 git/CLI、未登录、混用 CLI、缺工具链、PATH 与取消文件选择有明确反馈。
- [ ] 用临时仓库完成需求 → 发布工作包 → 编码或手写 → 检查 → QA → 人工验收 → 本地提交。
- [ ] 用实际工具链完成学习访谈 → lab 生成/自检/放置 → 提示/判卷 → 掌握度；记录生成通过率、耗时与费用。真实模型验收可能收费，构建工作流不执行。
- [ ] 验证默认沙箱与所宣称支持的独立账号模式；不可用时拒绝执行，不偷偷降低隔离。
- [ ] 分别在规划、编码、检查、lab 生成中正常退出及强退，重启后有中断提示与适当重试，不误标成功。
- [ ] 草稿跨重启可恢复/丢弃，切换仓库和旧基线不会覆盖新的正式内容。
- [ ] 以旧数据副本演练更新、备份、恢复和回退，检查外部笔记与移动仓库的重定位。
- [ ] JSON 损坏、未来格式、篡改备份、磁盘不可写与恢复中断时保留原件并提示恢复办法。
- [ ] 验证渲染进程崩溃后的重载入口、日志和诊断文本，实际费用/估算/未知费用及取消后的用量记录。

引入签名、公证或自动更新后，重新验证安装、权限和升级路径。
